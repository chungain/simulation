# 봉제 공장 둘러보기

공장 안을 직접 걸어 다니며 구역, 물건 흐름, 돌발 상황을 보는 2D 맵 도구입니다. 공장 하나는 시나리오 JSON 파일 하나로 표현합니다. 기획자는 웹 편집기에서 코드 없이 공장을 만들고 고칠 수 있습니다.

구현 계획의 **1단계(JSON 설정 분리와 코드 없는 편집)** 범위입니다. 화면 동작과 디자인은 「봉제 공장 둘러보기 UI/UX 기능명세서·디자인 가이드」를 기준으로 합니다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173 , scenarios/*.json 을 직접 읽고 씀
npm test           # 스키마·엔진 테스트
npm run validate   # scenarios/*.json 검증 (오류가 있으면 종료 코드 1, CI 용)
npm run build      # dist/ 정적 배포판 (읽기 전용, 링크 하나로 공유)
```

## 시나리오 종류

| 파일 | 종류(`kind`) | 내용 |
| --- | --- | --- |
| `scenarios/standard-factory.json` | `factory` (기본) | 봉제 공장 안: 입고부터 출하까지 9개 공정과 생산 관리실 |
| `scenarios/buyer-vendor.json` | `supply-chain` | 바이어 본사 · 벤더 사무실 · 공장·물류를 오가는 오더 흐름: MD의 PO부터 물류센터 정산까지 10단계와 소싱팀 |

바이어·벤더 시나리오에서는 서류(PO·테크팩·확정 오더) → 샘플 → 원부자재 → 완성품 → 카톤 → 컨테이너가 흐릅니다. 시간은 1초 = 1일이고, 시각은 "n주차 n일"로 보입니다. 피팅에서 샘플이 반려되면 수정 샘플(6일) 뒤 다시 검토하고, 검품에 떨어지면 재작업 뒤 다시 검품합니다. 돌발 상황은 샘플 반려 다발, 원단 입고 지연, 긴급 리오더, 선복 부족입니다. **구역 문구와 수치는 일반적인 업계 흐름으로 쓴 초안이라 현장 검수가 필요합니다.**

'공장 생산' 구역 카드의 **표준 봉제 공장 안으로 들어가기**를 누르면 공장 시나리오가 열립니다. 헤더의 `← 바이어·벤더 오더 흐름로` 버튼으로 돌아옵니다. 어느 구역이든 `zones[].link`에 다른 시나리오 id를 넣으면 이렇게 연결됩니다.

## 쓰는 법

**보기 화면** (기능명세서 F01~F14)
- 맵을 누르면 플레이어(나)가 그곳으로 걸어갑니다. 방향키나 WASD로도 움직입니다.
- 구역에 들어가면 설명 카드(하는 일, 현장 사람들, 시스템에 남는 데이터, 개발·디자인 포인트, 지금 재공)가 열립니다. 제목 줄을 누르면 접히고, 접힌 상태는 다른 구역에서도 유지됩니다.
- `공정 투어`: 사무실부터 출하까지 구역 목록 순서대로 데려가고, 구역마다 14초 머뭅니다. 탭이나 키를 누르면 멈춥니다.
- `전체 보기`: 공장 전체를 한 화면에 맞춥니다. 다시 누르거나 확대·축소하면 따라가기로 돌아갑니다.
- `속도`: 1×, 2×, 4× 순환. 플레이어 걷는 속도는 그대로입니다.
- `돌발 상황`: 진행 중이 아닌 것 하나를 일으킵니다. 자동으로도 하나씩 일어나고(끝난 뒤 40~65초), 진행 중에는 헤더에 남은 초가 뜹니다.
- `알림 켬·끔`: 돌발 상황 알림만 끕니다. 투어 완료 알림과 진행 중 배지는 그대로입니다.
- 시작하면 90초 분량을 미리 돌린 뒤 지표를 0으로 되돌리고, 게임 시각 08:00부터 셉니다(실제 1초 = 1분).
- 시스템 다크 모드와 `<html data-theme="dark|light">`를 따르고, 동작 줄이기 설정을 켜면 화살표 흐름·작업자 움직임·점멸이 멈춥니다.

**편집 모드**
- `선택`: 구역과 소품을 끌어 옮기고, 모서리를 끌어 크기를 바꿉니다. 오른쪽 패널에서 문구와 수치를 고칩니다.
- `경로`: 빈 곳을 누르면 경로 끝에 점이 붙고, 선 위를 누르면 그 사이에 점이 들어갑니다. 점을 오른쪽 클릭하면 지워집니다.
- `+ 구역`, `+ 소품`: 맵 위를 끌어 새로 그립니다.
- `JSON` 탭: 시나리오 전체를 텍스트로 고칩니다.
- 단축키: `⌘Z` 되돌리기, `⌘⇧Z` 다시 실행, `⌘D` 복제, `Delete` 삭제, 화살표 이동(`Shift`를 누르면 10px), `⌘S` 저장, `Space`+끌기로 화면 이동, `Alt`를 누른 채 끌면 격자에 맞추지 않음.

**시나리오 관리**: 상단 바에 새로 만들기, 복제, 가져오기, 내보내기, 저장이 있습니다. 저장하면 `scenarios/<id>.json` 파일에 그대로 기록되므로 Git으로 관리합니다.

**JSON 직접 편집과 실시간 미리보기**: `npm run dev` 상태에서 에디터로 `scenarios/*.json`을 고쳐 저장하면 화면이 바로 갱신됩니다. 파일에 오류가 있으면 이전 화면은 그대로 두고, 오류마다 `파일:줄:칸`, 항목 경로(예: `zones[2](cut).station.time`), 한국어 설명을 보여줍니다. 오류를 누르면 JSON 탭의 해당 줄로 이동합니다.

## 시나리오 파일

스키마는 `src/schema/scenario.schema.json`입니다. 시나리오 파일 첫 줄의 `"$schema"` 덕분에 VS Code에서 자동 완성과 검사가 됩니다.

| 항목 | 내용 |
| --- | --- |
| `layout` | 맵 크기, 플레이어 시작 위치(`start`), 소품·사람(`props`: 미싱, 재단기, 다리미판, 현황판, 트럭, 작업자, 관리직 등) |
| `view` | 걷는 속도(170), 따라가기 배율 기준(420), 투어 머무는 시간(14), 알림 시간(9), 재공 경고 개수(6) |
| `stages` | 물건 상태와 모양(원단 롤, 연단, 재단물, 번들, 티셔츠, 박스), 체크 표시. 색을 비우면 물건마다 받은 원단 색 |
| `zones` | 배열 순서 = 투어 순서. 위치·크기(`rect`), 아이콘, 사무실 표시(`hub`), 공정(`station`), 설명 카드(`content`) |
| `zones[].station` | 자리 공정: 처리 시간·편차·동시 처리 수·처리 자리 / 라인 공정: 흐르는 속도(`speed`). 처리 후·처리 중 상태, 검사·불량률·수선 시간(`repair`) |
| `flow` | 경로 점, 투입 간격(3.2), 통로 속도(60), 물건 간격(22), 원단 색 6가지, 예열(90), 게임 시각 시작·배율 |
| `eventTiming` | 돌발 상황을 하나씩: 끝난 뒤 `[40, 65]`초, 버튼으로 일으킨 뒤 45초 |
| `events` | 아이콘, 이름, 화면에서 보이는 것, 현장 포인트, 지속 시간, 영향(`stopZones` 정지, `spawnMultiplier` 투입 배수, `defectRate` 불량률로 바꿈, `defectZones` 불량률을 바꿀 검사 구역) |
| `kind` | `factory`(공장 안) 또는 `supply-chain`(바이어·벤더). 헤더 제목과 카드의 "공정/단계" 표시가 바뀌어요 |
| `layout.areas` | 바이어 본사·벤더 사무실처럼 구역을 묶는 큰 영역 `{ name, icon, rect }`. 편집 패널의 '영역'에서 고쳐요 |
| `zones[].link` | 카드에서 들어갈 다른 시나리오 id |
| `flow.clockFormat` | `time`(08:00) 또는 `day`(n주차 n일, `timeScale: 86400` 이면 1초 = 1일) |

물건은 경로를 따라 움직이다가 공정이 있는 구역에 닿으면 처리 자리가 빌 때까지 기다립니다. 처리가 끝나면 상태가 바뀌고, 다음 자리가 비어 있을 때만 구역을 나갑니다. 그래서 공정 사이 공간이 좁으면 막힘이 앞 공정으로 번집니다. 라인 공정(봉제)은 자리 없이 구역 안을 천천히 흐르며, 진행할수록 진하게 보입니다. 검사에서 불량이 나오면 수선 시간 뒤 다시 검사합니다.

**계획서 예시 JSON과 다른 점**: 맵 크기와 소품을 담는 `layout`, 물건 모양을 담는 `stages`를 필수로 했습니다. 돌발 상황의 `interval`은 선택 항목이고, `eventTiming`이 있으면 쓰지 않습니다.

**기능명세서와 다른 점**
- 표준 공장 맵은 명세의 960×760 크기와 수치를 따르지만, 구역 배치·소품 위치·설명 문구는 기존 프로토타입을 보지 못해 새로 그렸습니다.
- 봉제 라인은 늘 재공이 11개 안팎이라 이 구역만 재공 경고를 16개로 올렸습니다(`zones[].wipWarn`).
- 다크 모드의 강조색 버튼(`--accent` #4fb3a8)은 흰 글자 대비가 낮아 진한 글자를 씁니다(`--onAccent`).
- 개선할 점 중 "동작 줄이기 시 화살표·작업자·점멸 멈춤"과 "모바일에서 알림이 확대 버튼을 가리는 문제"는 고쳤습니다. 구역 키보드 목록, infoBtn 정리(이번 코드에는 없음), 진행 중 배지 닫기는 남아 있습니다.

## 코드 구조

```
src/sim/          시뮬레이션 엔진, 경로 계산, 난수 (DOM을 쓰지 않음 → 3단계 Three.js에서 재사용)
src/render/       Canvas 2D 렌더러 (색은 CSS 디자인 토큰에서 읽음)
src/view/         둘러보기: 플레이어 이동, 구역 진입, 공정 투어 (DOM 없음)
src/editor/       맵 편집(editor.js), 속성 패널(panel.js)
src/schema/       JSON Schema, 검증(줄 번호·한국어 메시지), 저장 형식
src/api.js        시나리오 저장소 (개발 서버 API / 정적 배포 대체)
vite.config.js    /api/scenarios 읽기·쓰기, 파일 변경 감지 → 브라우저 갱신
scripts/validate.mjs  검증 CLI
tests/            검증·엔진 테스트 (vitest)
```

## 계획서 1단계 작업 대응

| 작업 | 구현 |
| --- | --- |
| 스키마 설계 | `scenario.schema.json`, 표준 공장 시나리오(10개 구역, 돌발 상황 4종) |
| 엔진 개편 | `sim/engine.js`, 설정만 읽어 그리고 움직이며, 같은 seed면 같은 결과 |
| 검증과 오류 표시 | `validate-core.js`: 문법, 스키마, 참조(없는 상태·구역, 겹치는 id), 배치 경고(맵 밖, 경로가 공정을 지나지 않음) |
| 웹 편집기 | 구역·소품 끌기와 크기 조절, 경로 편집, 처리 자리 편집, 속성 패널, JSON 탭, 되돌리기 |
| 시나리오 관리 | 저장, 새로 만들기, 복제, 내보내기, 가져오기(같은 id면 새 id 또는 덮어쓰기) |

완료 기준인 "기획자가 새 공장 레이아웃 하나를 하루 안에 코드 없이 만든다"는 실제 기획자가 해 봐야 확인할 수 있습니다.
